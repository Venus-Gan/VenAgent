# Outcome

完成对 `D:\VSCProject\AGI-saber` 的代码级架构审计，形成 VenAgent 由简至繁、逐阶段审批的重构总方向；本变更只产出审计和路线，不实现任何新功能。

# Scope

- 盘点旧项目的后端、前端、Agent、记忆、RAG、工具、沙箱、Skill、文档、认证、持久化和基础设施。
- 核对关键执行流、数据边界、测试现状与显著风险，而不是只复述 README 或旧架构文档。
- 对比 VenAgent 已完成的最小 Agent Loop 与真实模型适配器，识别后续依赖顺序。
- 给出总体架构方向、阶段划分、每阶段进入/退出边界和明确延期项。
- 将路线提交用户审批；审批后仍需逐阶段重新分析、取舍和确认。

# Non-goals

- 本变更不实现会话记忆、持久化、工具、RAG、认证或其他运行时能力。
- 不把 `AGI-saber` 代码直接复制到 VenAgent，也不承诺复刻全部功能。
- 不在本轮确定每个阶段的详细数据模型、API 或基础设施选型；这些属于阶段 Shape。
- 不修改或运行旧项目的外部基础设施，不使用真实凭据进行联调。

# Acceptance examples

- 审计报告能回答旧项目有哪些模块、核心功能、关键数据流、技术依赖和测试覆盖。
- 审计能区分值得保留的行为、必须重写的边界和可延期或舍弃的功能。
- 路线能说明每阶段为什么排在当前位置、交付什么、明确不做什么以及完成门槛。
- 用户可以对总体方向和阶段划分作出批准、修改或否决，而无需先接受任何功能实现。

# Constraints and invariants

- `AGI-saber` 仅作功能与行为参考，不作为源码迁移目标。
- VenAgent 继续使用 Python 3.11、FastAPI、LangChain/LangGraph 和现有 Web UI 基线。
- 对话状态、业务记忆、任务 checkpoint、知识库和运行事件必须保持概念分离。
- 每个阶段使用独立 Comet change，重新完成 Shape、Build、Verify、Archive；路线批准不等于自动批准各阶段实现。
- 涉及用户数据、凭据、工具执行、MCP 或外部网络时必须保持最小权限和可审计性。

# Decisions

- 采用选择性重构，不做全量翻译或一次性交付。
- 已完成的 Phase 0 为最小单节点 Agent Loop、OpenAI 兼容真实模型适配器和基础 Web UI。
- 下一阶段优先修正会话语义：以 `thread_id` 作为对话边界，避免旧项目仅按 `userID` 聚合全部对话。
- 初始内存后端可以是进程内实现，但线程契约、状态结构和清理语义必须可长期保持。
- 旧项目的偏好、长期语义记忆、任务状态、工具观察和聊天历史不得继续统称为一个“记忆模块”。
- 完整路线划分为 Phase 0（已完成）和 7 个后续阶段；每阶段单独审批和取舍。
- 用户已于 2026-07-23 批准 `audit.md`、`roadmap.md` 和拟议路线规范；批准只确定总体方向与阶段边界。
