# M08 文档库范围与检索契约（grilling 票）

> 状态：**closed**（2026-08-05 session 拍板；Q1-Q6 + OCR 全部 resolve）。下一步：Shape（目录增量/接口契约/前端表面）→ 用户确认 → 实现授权。

## 背景（对照结论要点）

- AGI-saber：文档库**全局单租户**（三表无 user_id）、**无状态机**（仅 active）、Ingest **全同步无进度**、**无文档级删除 API**、**无 citation 结构**（证据=SearchResult 数组+SSE 事件，回答无引用编号）、上传(/api/upload)与文档库(/api/documents)双路径割裂、工具已下线走 mode 路由。
- 检索：RRF `Σw/(k+rank+1)`、k=60、KG=0.3、fetchK=2×topK、rerankPool=4×/2×topK、topK=3；Milvus L2 dim 2048 pg_id 主键；ES BM25 `_id`=pg_id；Neo4j LLM 抽实体→apoc 子图 max_hops 2→pg_id 汇 RRF；模式 hybrid/semantic/keyword/unavailable + 查询期逐路降级；small-to-big 子 200/50、父 max(4×200,600)/100；切分器=分隔符优先级表+代码块原子+贪心合并。
- VenAgent 语境：M04/M05 已建立 **owner 隔离传统**（跨 owner 测试是验收要素）；memory 有删除/禁用/清空治理链路；capability registry 统一降级语义（ADR-0001，不静默吞错）。

## Q1 文档来源与格式（第一期）

- 选项 A（推荐）：**上传 API**（`POST /api/documents` multipart）+ 格式 = 纯文本/markdown 全收 + **PDF 特殊抽取**（pdfplumber → 失败报「需要 OCR」拒收，对齐 AGI-saber 三级降级）；64MB 上限；空文档报错。
- 选项 B：仅 txt/md，不做 PDF（少一个外部依赖，覆盖面窄）。
- 选项 C：加 docx（需 python-docx 依赖）。
- 附带决定：**不做本地目录扫描**（AGI-saber 无此路径；扫描目录引入文件系统权限与同步复杂度，与上传 API 重复）。

## Q2 文档生命周期（状态机 / 删除 / 进度）

AGI-saber 全同步、无删除、无进度。VenAgent 建议（对齐 memory 治理传统）：
- 选项 A（推荐）：**文档状态机** uploaded→parsing→chunking→indexing→ready / failed（解析或索引失败可重试/删除）；**文档级删除 API**（软删 status + 硬删事务：PG 先删 chunk 拿 ids → ES `_id` 逐删 → Milvus 表达式删；删除失败记录为可观测降级而非静默）；**索引进度暴露**（文档返回 indexed_count/chunk_count，列表带状态；大文档走后台任务）。
- 选项 B：对齐 AGI-saber 全同步（响应即完成），无状态机/删除/进度，留二期。
- 附带：重传 = 新版本（version+1）或覆盖（同 doc_hash upsert）？——建议版本化（AGI-saber document_versions 语义），重传生成新版本并重新 Ingest。

## Q3 隔离（owner 边界）

- 选项 A（推荐）：**per-owner 文档库**——documents/versions/chunks 建表带 owner_id；上传/列表/删除/检索全部按 owner 过滤；跨 owner 隔离测试纳入验收（与 M04/M05 一致；AGI-saber 全局共享被对照列为风险点 8）。
- 选项 B：对齐 AGI-saber 全局单租户（表预留 owner 列不启用过滤，二期再做）。
- 提示：per-owner 会改变检索接口（需 owner 过滤参数）与前端（文档列表按登录用户），但与 VenAgent 所有权体系一致，且避免一期全局、二期迁移。

## Q4 图路一期范围（ADR-0006 冲突点）

ADR-0006 拍板三路（含 Neo4j）；对照建议 KG 路一期可省（独立权重 0.3、异步建图、缺席仅影响召回广度）。
- 选项 A：**完整三路**（Milvus+ES+Neo4j）——Neo4j 已有容器与驱动先例（M05），KG 路=LLM 实体抽取 + apoc 子图扩展（max_hops 2）+ pg_id 汇 RRF；工作量最大。
- 选项 B（推荐？）：**两路先行（Milvus+ES），KG 图路二期**——RRF 架构/降级链/接口按三路设计（KG 路可插拔），一期 `kg_weight` 生效但无图源（该路恒降级）；二期补 kgstore 无需改检索契约。**需用户明确改 ADR-0006**（或理解为 ADR 的图路实现分期）。

## Q5 证据引用结构（ADR-0006「证据引用回答」落地）

AGI-saber 无 citation，回答纯文本拼接上下文（对照风险点 9）。VenAgent 必做新增：
- 选项 A（推荐）：**结构化引用**——检索结果携带 document 溯源（document_id/title/section/chunk）；LLM prompt 带编号引用 `[1][2]`（仅允许引用给定编号，来源不足必须说明）；前端展示引用块（来源文档标题 + 原文片段）。
- 选项 B：仅返回 SearchResult 数组（对齐 AGI-saber），引用编号不做。

## Q6 验收与触发方式（M08 独立验收的入口）

M07 Selector 三支归 M07；M08 需要自己的验收触发路径：
- 选项 A（推荐）：**聊天命令 `/rag <query>`**（类似 /memory 命令模式，走命令适配器）→ 返回检索结果（含降级标记 source=hybrid/keyword/semantic +rerank）与引用结构；前端展示引用。M07 时 Selector 直接调用同一 rag service。
- 选项 B：纯 HTTP API 验收（curl 调 search 接口），前端不做。
- 选项 C：chat 自动触发（需要 M07 路由，本模块不做）。

### 附带决定（Q1 追问：OCR 需要考虑什么）

- **决定：一期拒收，二期 RapidOCR。** 扫描件/图片型 PDF → 状态机 `failed(reason=needs_ocr)` + 明确报错「该 PDF 为扫描件/图片型，需要 OCR 支持」+ 可删除重传。一期不引入 OCR 能力（对齐 AGI-saber），不撑大 M08 范围。
- 二期候选：RapidOCR（rapidocr-onnxruntime，pip 可装无系统二进制、中英文、onnx CPU 推理）——parsing 降级路径、置信度 <0.5 丢弃、页数上限、OCR 内容同走注入面检查。PaddleOCR/Tesseract/云 OCR 已排除（依赖重/需系统安装/需密钥）。
- 该附带决定已在 M08 intake「待定决策」标注。
