## Question

「完成整个项目、让它成为可靠 agent」的具体范围与顺序，钉死四件事：
1. **子模块顺序**（推荐承接已锁定路线）：M06 单工具闭环 → **多工具** → M08 RAG（文档摄入/检索/证据，当前全缺席）→ memory/promptctx 重构落地 → sandbox/skills/MCP/command 补齐 → **最后**路由 + 动态图编排（langgraph 特色）整合。
2. 每个子模块的**完成标准/验收口径**（测试口径见 `tests 重组规范`，避免「验证过重」）。
3. **「可靠 agent」完成标准**（推荐基线 = 路线模块全部实现 + 真实多步任务跑通；验收门槛 = 真实浏览器 Verify：发送/流式/断线恢复/审批/工具副作用幂等/跨 owner 隔离）。
4. langgraph 特色（动态 DAG、Planner/Selector/Replanner、interrupt HITL、checkpoint 恢复）如何与既有单工具闭环**正交**。
产出 = 路线规划文本（进 `docs 重建与 AGENTS/CLAUDE 改造` 票）。

## Resolution

**RESOLVED**（grilling 多轮，用户逐项拍板；Q2 依据只读现状调查子代理报告按模块细化）：

1. **子模块顺序（Q1 已锁定）**：M06 单工具闭环（现状基线）→ **多工具** → M08 RAG（文档摄入/检索/证据）→ memory/promptctx 重构落地 → **sandbox/skills/MCP/command 对齐与验证**（现状调查确认三者已完整实现，此步只做对齐 + 验证 + 文档化，非补齐）→ **最后** 路由 + 动态图编排（langgraph 特色）整合。与 m06 草案 `M06 → M08 → M07` 一致。
2. **多工具交互形态（Q6 已定，两阶段）**：过渡期结束后第一版**纯顺序执行**（每步仍过 M06 校验、可审计、断线恢复语义简单）；层内并行（MaxParallel 2）/竞速 RaceGroup 作为后续增强，与 M07 编排整合时一起做（依赖关系建模需 Plan 层配合）。
3. **路由与执行层边界（Q7 已定）**：Selector = 意图路由节点，编排层第一步做意图判断，**隐性分发三支：ReAct / RAG / 直接回答**；无前端开关、无用户手动选模式。意图判断用快速规则 + 模型判断组合（AGI-saber 参考：未显式选择时用快速规则判断天气/时间/搜索/知识库等意图）。**不设记忆分支**——记忆保持现有「每次 run 自动注入」路径（recall.py → promptctx → ContextBlock），「明确回忆」扩大召回档位留在记忆模块内，不进路由。
4. **M08 RAG 范围（Q5 已定，三路 RRF 迁移）**：Dense（Milvus 语义）+ BM25（Elasticsearch 词法）+ Neo4j 图检索 → RRF 融合（**固定权重照搬 AGI-saber**）→ 可选 LLM rerank → small-to-big 父子上下文 → 证据引用回答。**Milvus/ES 驱动与固定 RRF 权重进入 RAG 实现时迁移**（用户拍板推翻 Do-not-copy:249）；按 AGI-saber Go 驱动的索引/检索模式用 Python 客户端（pymilvus/elasticsearch-py）实现；基础设施 compose 增加 Milvus + ES 服务（参照 Neo4j 加入根 compose.yaml 先例）；逐路降级照 final/internal/rag/hybrid.py 模式。**不复刻 AGI-saber「tool/chat 顶级模式 + 前端开关选模式」**。embedding 复用独立通用 port（llm/embeddings.py 技术 port），M05 记忆与 M08 RAG 共享技术 port 但不共享事实/索引/生命周期（comet/specs/llm-runtime-configuration.md:11）。RAG 模块完成标准将含真实 Milvus/ES 集成测试（与 M05 的 PG+Neo4j 集成先例一致）。
5. **「可靠 agent」完成标准（Q3 已定）**：路线模块全部实现 + 真实多步任务跑通；最小跑通集 = 单个多步任务（≥2 工具调用 + 1 次 M06 审批 + 中途断线恢复后完成），浏览器 Verify 覆盖发送/流式/恢复/审批四要素；外加工具副作用幂等、跨 owner 隔离。
6. **langgraph 特色正交性（Q4 已定）**：单工具闭环是执行层（每步仍走 M06 权威），图编排是外层计划层（Planner→Selector→Executor→Replanner），两层通过稳定 Plan/NodeOutcome identity 对接。Replanner 事件驱动（节点失败/观察不足/依赖失效/前提改变）+ 完整 Plan revision；NodeOutcome 用稳定 identity 归并；不使用 create_deep_agent；主 Agent 不兼任计划修改/工具授权/审批恢复/终止判断。
